# Tidegaze THVS · 出口管制信息监测（V1 本机版）

Tidegaze（观潮）取自原名“观澜”。界面、邮件标题和发件人名称都使用这个名字；修改 `app/config.py` 里的 `APP_NAME` 和 `frontend/src/format.ts` 里的同名常量即可更换。

在自己的 Windows 电脑上实时监测**中国出口管制信息网**的五个栏目，发现新发布、正文修订和附件变化后，在网页里显示，并按设置发送邮件。

| 栏目 | 官网栏目号 | 默认检查新发布 | 默认复查正文 | 默认邮件 |
|---|---|---|---|---|
| 法律 | 13 | 每 5 分钟 | 每 6 小时 | 即时 |
| 法规 | 14 | 每 5 分钟 | 每 6 小时 | 即时 |
| 规章及规范性文件 | 15 | 每 5 分钟 | 每 6 小时 | 即时 |
| 国内动态 | 1 | 每 5 分钟 | 每 24 小时 | 每日汇总 |
| 国际动态 | 2 | 每 5 分钟 | 每 24 小时 | 每日汇总 |

每一项都能在网页的「栏目」里单独修改。

## 启动

需要 Python 3.11+ 和 Node.js 20.19+。在项目目录打开 PowerShell：

```powershell
.\start.ps1              # 在当前窗口运行，Ctrl+C 停止
.\start.ps1 -Background  # 在后台运行，意外退出会自动重启，并打开网页
.\stop.ps1               # 停止后台运行
```

浏览器打开 http://127.0.0.1:8840 。首次运行或依赖变化时，脚本会自动安装 Python 包并构建前端；也可以加 `-Install` 强制重装。

**开机自动运行**：在网页「邮件通知 › 这台电脑」里打开“登录 Windows 后自动在后台启动”，或运行 `.\scripts\autostart.ps1`（取消：`-Disable`）。

**电脑睡眠**：睡眠或关机期间无法检查。默认开启“运行时阻止电脑自动睡眠”，显示器照常关闭，手动睡眠不受影响。电脑恢复后，第一次检查会自动补上中间漏掉的新文章（继续往后翻页，直到遇到已收录的文章）。

## 邮件通知

在网页「邮件通知」里填写发件邮箱：

1. 选择邮箱服务商，服务器、端口和加密方式会自动填好。
2. 填写邮箱账号和**授权码**。QQ 邮箱、163 邮箱等需要在邮箱网页版的设置里开启 SMTP 服务，然后生成授权码。授权码不是登录密码。
3. 添加收件人，点“保存并发送测试邮件”，收到后打开右上角的开关。

规则如下：

- **即时邮件**：设为“即时”的栏目一有变化就发。同一批变化会先等待合并（默认 2 分钟）再一起发出。新文章会等正文抓取完成后再发，最多等 10 分钟，这样邮件里能带上标题和摘要。
- **每日汇总**：每天北京时间 18:00（可改）发送设为“每日汇总”的栏目的变化，并附上各栏目当前的检查状态。默认也会回顾当天已经即时发过的内容。当天没有变化时默认不发。
- **故障提醒**：某个栏目连续 3 次检查失败时发一封提醒，恢复正常后再发一封。
- 开启邮件之前发生的变化不会补发。发送失败会自动重试，可在“发送记录”里查看原因或手动重发。
- 在 Windows 上，授权码用当前 Windows 账户加密后保存，复制数据库到其他电脑或账户无法解密。

## 工作方式

- **发现新发布**：按设定频率请求各栏目列表的第一页。只有第一页全是新文章时才继续往后翻，最多翻 5 页。每天另做一次完整分页核对，用来发现被跳过或调整顺序的条目。
- **正文修订**：读取文章页 `.u-art-box .bd` 区域的正文，统一空格和换行后比较。页面导航、页脚免责声明和样式变化不算修订；标题变化算修订。
- **附件**：正文里链接的 PDF、Word、Excel 等文件会下载保存，按 SHA-256 判断是否变化。PDF 会提取前 50 页的文字，方便对比。文件字节变化不一定代表政策内容变化，页面上会单独标明。
- **请求节制**：对官网的请求至少间隔 1.2 秒。失败后按次数逐步延长重试间隔。不会关闭证书校验。
- **首次基线**：新栏目第一次检查只建立基线，不会把历史文章当作新发布提醒；官网列表返回空时不会删除已有数据。

## 从旧版本升级

第一次启动新版本时，程序会自动从旧数据库 `data/observatory.sqlite3` 导入文章、栏目归属、附件和已保存的文件。旧版正文是 changedetection.io 的格式，导入时会用旧引擎保存的网页快照、按新规则重建基线，所以不会把格式差异误报为修订。导入后，所有文章会在一小时内各复查一次，旧版停止运行之后官网发生的真实变化仍会被发现。

旧数据库和 `data/engine/` 只读取、不修改。如需退回旧版，停止服务后切回 `main` 分支即可。旧引擎数据确认不再需要后，可以手动删除 `data/engine/` 和 `data/attachments/`。

## 数据与备份

- 数据库：`data/guanlan.sqlite3`（结构见 [DATABASE.md](DATABASE.md)）
- 附件文件：`data/files/`
- 日志：`logs/guanlan.log`（自动轮换），后台守护进程的日志在 `logs/supervisor.log`

备份不需要停止服务：

```powershell
.\.venv\Scripts\python.exe scripts\backup.py
```

备份文件保存在 `backups/guanlan-时间.zip`。恢复时先运行 `stop.ps1`，把当前 `data/` 改名保留，再把备份里的 `data/` 解压到项目目录，最后启动。

## 安全边界

服务只监听 127.0.0.1，拒绝其他主机名的请求，也拒绝其他网页发起的修改请求。没有登录功能，不要把 8840 端口转发到公网。

## 开发与测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -t . -v
cd frontend; npm run build
```

测试使用临时目录和模拟官网，不访问网络，也不写入真实数据。`tests/fixtures/` 里是从官网保存的三个真实页面，用来验证正文提取。

| 模块 | 作用 |
|---|---|
| `app/site.py` | 官网适配：列表接口、文章正文、附件链接 |
| `app/fetch.py` | 访问官网：域名白名单、证书校验、请求间隔、重试 |
| `app/monitor.py` | 列表检查、正文和附件复查、事件记录 |
| `app/notify.py` | 即时邮件、每日汇总、故障提醒、发送队列 |
| `app/worker.py` | 后台循环：列表、正文、邮件各一个线程 |
| `app/legacy.py` | 一次性导入旧版数据 |
| `app/main.py` | 网页接口 |
| `frontend/src/` | 网页界面（React + TypeScript） |

小程序与服务器版在 `feat/wechat-miniapp-v2` 分支，与本版本相互独立。
