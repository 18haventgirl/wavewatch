## P1 第二批：正文与附件模块

- 结构升级到 0002_monitoring，新增独立 inspect/sync 时间、错误、暂停状态、历史水位与规则重建基线标记。0001 历史定义保持冻结，新增迁移保留原有数据。
- 独立 inspector 核实文章标题、提取附件、建立共享附件关系；初始附件基线不批量制造提醒。
- 独立引擎适配器显式接收专用 URL 和 key，校验 watch 与文章 URL；不读取旧引擎目录的凭证。
- 同步按时间顺序分批补齐历史；相同内容不重复保存，历史水位防止重复快照阻塞后续版本。
- 提取规则变更先持久化基线标记，再改引擎规则；重试仍保留标记，避免把规则变化当作政策变化。
- 附件按 SHA-256 原子保存，A→B→A 保存三次变化；原文件未变时，提取说明文字调整不产生修订。PDF 在独立进程限时提取，扫描件保留完整原文件和明确说明。
- 共享文章采用未暂停栏目中的最短检查间隔；全部栏目暂停时同步引擎暂停，恢复后重新开启。
- 详情接口提供版本、差异、附件、采集状态；附件下载须验证开发管理身份。
- 新调度设置 64 个在途文章任务上限和每轮 32 个任务上限，避免正文/附件任务挤满数据库。

真实端到端验证已通过：官网文章 226《中华人民共和国出口管制法》→ 独立 changedetection.io 0.70.4 → 新库保存 1 个版本（7,181 字符）→ 身份保护的详情接口返回正确标题和正文。证据目录 data-v2/live-monitor-48u6zl3f，测试引擎已停止。原本机版未切换。

本批服务器测试共 42 项通过：SQLite/接口/迁移 20 项，真实 PostgreSQL 22 项；包含新增正文、附件及重建基线失败恢复场景。当前活动库再次导入临时 PostgreSQL 并通过逐表核对。Linux 镜像构建本轮重试仍在获取 Python 基础镜像时遭遇连接重置，仍列为待验证，不以 Windows 进程链路成功替代 Linux 容器验收。
